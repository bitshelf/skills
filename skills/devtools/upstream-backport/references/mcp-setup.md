# 可选工具配置

最小工作环境是 shell、curl、Git 及本地源码搜索；MCP 不是 backport 的必要条件。先使用当前可用工具，仅在任务确实受阻或用户请求安装时添加服务。

| 工作 | 可选工具 | 无 MCP 回退 |
|---|---|---|
| 上游页面、commit、补丁 | 浏览器、Fetch、托管平台连接器 | curl 及随附 fetch_patch.sh |
| 版本/API 理解 | 官方文档检索、Context7 | 对应版本源码和官方资料 |
| 架构线索 | DeepWiki 等 | 仓库文档、源码；生成摘要需回原文验证 |
| 本地版本状态 | Git MCP | git status/log/show/diff |
| 符号与调用关系 | semcode、Serena | rg 和源码逐处核对 |

服务名称、维护状态、包版本、安装命令和客户端配置会变化，按当前官方说明核对；不沿用未经验证的版本号或笼统“已归档”断言。保留已有项目 MCP 配置，凭证按客户端支持的方式提供，不写进可分享文档或命令日志。

C/C++ 语义工具按实现可能需要正确的 compile_commands.json。使用当前构建系统或内核支持的生成方式，核对源码/对象目录；不能要求所有内核都支持同一 make 目标。索引缺失时说明文本回退的限制，不中断可完成的分析。

Gerrit/gitiles 的补丁响应格式、GitLab 实例的 API 能力、私有仓库认证均以当前端点和版本为准。HTTP 错误、HTML 页面和截断补丁不能当作源码证据。
